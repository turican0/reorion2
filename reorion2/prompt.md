-pointers in game structures (x64): the target is real C structs whose pointer fields have the proper pointer type (8 bytes on x64). Everything that must keep the original byte layout (saves, LBX and other game files, network packets, comparison with DOSBox) gets a shadow twin of the struct with the original 32-bit layout: `type_shadow_<name>`, packed, every pointer as a 32-bit value, a static_assert on the original size. Data cross the boundary only in `Convert_from_shadow_<name>` / `Convert_to_shadow_<name>` at load, save and I/O - the same scheme as remc2 (engine_support.h `type_str_E2A74` / `type_shadow_str_E2A74`, Basic.cpp `Convert_to_shadow_str_E2A74`, Level.cpp `Convert_from_shadow_D41A0_BYTESTR_0`)
-in the shadow a pointer is stored the way the original stored it, so the files stay byte identical: an offset from the base the original used (remc2: `ptr - Zero_pointer`), 0 stays NULL; when the pointer always points into one known array, the conversion may compute it from the index, but the stored value is the original one
-a field that the original uses as a pointer at one time and as a 32-bit number at another (Hex-Rays shows int at some sites, a pointer at others) becomes a union in the runtime struct (`union { T *ptr; int32_t value; }`); the union exists only in the runtime struct - the shadow keeps one uint32_t, and the conversion decides from the context (flag, record type, the code that wrote it) which member is valid; never guess - check the asm of the writers
-until a struct is written this way (the current state): the field stays a 32-bit slot in dseg/eseg, pointers in it are 32-bit (the build is LARGEADDRESSAWARE:NO, so addresses are below 2 GB); read them only with `PORT_PTR32` / `(T *)(uintptr_t)*(uint32_t *)slot`, never as `*(T **)slot` - that reads 8 bytes and takes the next field as the high half (bug found 2026-11-03 in sub_D94B3, `*(_BYTE **)((char *)&a25 + 2)`); the same for the high word of a pointer copied into an int (`HIWORD(v) = HIWORD(dword_19306C)`) - on x64 it is not the value the original had
-16-bit values passed in 32-bit registers: Watcom callees often read only the low word (movsx/cwde/test ax,ax) and the caller leaves junk in the high word, which the original ignores; such a parameter is int16_t (with a full prototype at every caller), until then `aN = (int16_t)aN;` at the start of the function; do not zero the high half in the caller instead
